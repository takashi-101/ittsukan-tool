# 要件定義（一気通貫ツールの工程1）

## 概要（30秒で読めます）

- **この工程で詰まっている会社向け**：何から決めればよいか分からない、現場の話がまとまらない。
- この画面で、何に困っていて、何ができればよいかを決める。
- 結果は「工程票（こうていひょう）」というJSONにまとまり、次の工程で読み込めます。人が読む用のMarkdownでも書き出せます。
- AIを使わなくても、入力・点検・書き出しはすべて動きます。入力した内容はブラウザの中にだけ保存し、どこにも送信しません。
- このフォルダだけを取り出しても動きます（`index.html` をブラウザで開くだけ）。

## 入力と出力

| | 内容 |
|---|---|
| 前の工程の工程票（任意） | なし（最初の工程） |
| この工程で書くもの | 現状の業務（W）、困りごと（P）、目的（G）、必要な機能（R）、対象外にすること（X） |
| 書き出すもの | `01-yoken.json`（工程票）、`01-yoken.md`（人が読む用） |

## この工程の道具

- 業務棚卸し（gyomu-tanaoroshi）で書き出したJSONから、現状の業務を読み込む

## 点検（AIは使わない）

入力のたびに、決まりで次を調べて「点検の結果」に出します。

- 必須の欄の空き
- 「もとになった項目」の番号が、前の工程の工程票につながるか
- 目的につながっていない困りごと（要対応）
- 機能が一つも無い目的（要対応）
- 「架空の基準」と書いた決まり（参考。本番の前に実在の基準へ置き換える）

## 欄の説明

### 現状の業務（W）

今、誰がどんな手順でしている仕事か。業務棚卸し（gyomu-tanaoroshi）のJSONから読み込めます。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 業務名 | 必須 |  |
| 担当（課・係と役割。個人名は書かない） |  |  |
| 今の手順 | 必須 |  |
| 月の作業時間（時間） |  |  |
| 課題のメモ（滞留・手戻り・割り込みなど） |  |  |

### 困りごと（P）

現場で起きている困りごと。どの業務で起きているかを「もとになった項目」に書きます。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 困りごと | 必須 |  |
| 具体的な様子（いつ・どのくらい） |  |  |

### 目的（G）

この仕組みで何を良くしたいか。良くなったかの確かめ方も書きます。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 目的 | 必須 |  |
| 確かめ方（何がどうなればよいか） | 必須 |  |

### 必要な機能（R）

目的のために要る機能（要件）。どの目的のための機能かを「もとになった項目」に書きます。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 機能 | 必須 |  |
| 内容 | 必須 |  |
| 優先度 | 必須 | 必須・できれば・今回は見送り |

### 対象外にすること（X）

今回は作らない・扱わないと決めたこと。後で「頼んでいない」「入っていない」の食い違いを防ぎます。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 対象外にすること | 必須 |  |
| 理由 |  |  |

## 見本

画面の「見本案件（放課後児童クラブの利用申請）を読み込む」で、架空の市の案件を表示できます。前の工程の工程票も見本のものを読み込みます。

## AIアプリから使う

リポジトリの `mcp/` にあるMCPサーバーを Claude Desktop か LM Studio に登録すると、AIアプリがこの工程の工程票を読み書き・点検できます。手順はリポジトリ直下のREADMEにあります。
