# 導入（リリース）（一気通貫ツールの工程6）

## 概要（30秒で読めます）

- **この工程で詰まっている会社向け**：できたものを、現場でいつ・どう使い始めればよいか分からない。
- この画面で、現場に渡す手順、切り替えの段取り、使う人への説明を用意する。
- 結果は「工程票（こうていひょう）」というJSONにまとまり、次の工程で読み込めます。人が読む用のMarkdownでも書き出せます。
- AIを使わなくても、入力・点検・書き出しはすべて動きます。入力した内容はブラウザの中にだけ保存し、どこにも送信しません。
- このフォルダだけを取り出しても動きます（`index.html` をブラウザで開くだけ）。

## 入力と出力

| | 内容 |
|---|---|
| 前の工程の工程票（任意） | 要件定義、テスト（検収） |
| この工程で書くもの | 現場へ渡す手順（LS）、切り替えの段取り（LC）、使う人向けの説明（LE）、よくある問い合わせ（LQ） |
| 書き出すもの | `06-donyu.json`（工程票）、`06-donyu.md`（人が読む用） |

## この工程の道具

- 必要な機能から、現場へ渡す手順の下書きを作る
- 使う人向けの説明を印刷する（A4）
- よくある問い合わせを、窓口回答標準化ツール（madoguchi-kaito）の標準回答台帳（JSON）として書き出す

## 点検（AIは使わない）

入力のたびに、決まりで次を調べて「点検の結果」に出します。

- 必須の欄の空き
- 「もとになった項目」の番号が、前の工程の工程票につながるか
- 導入の手順が無い必須の機能（要対応）
- 「架空の基準」と書いた決まり（参考。本番の前に実在の基準へ置き換える）

## 欄の説明

### 現場へ渡す手順（LS）

使い始めるまでにすること（設定、配る物、研修など）。どの機能のための手順かを書きます。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| すること | 必須 |  |
| する人（係・役割） | 必須 |  |
| いつまでに |  |  |
| 内容 |  |  |

### 切り替えの段取り（LC）

今のやり方から新しいやり方へ移る順番。並行して使う期間と、元に戻す方法も書きます。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 段階 | 必須 |  |
| 期間 | 必須 |  |
| 内容 | 必須 |  |
| うまくいかないときに元に戻す方法 | 必須 |  |

### 使う人向けの説明（LE）

使う人（住民・職員など）に向けた説明。A4で印刷できます。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 見出し | 必須 |  |
| 読む人 | 必須 |  |
| 本文 | 必須 |  |

### よくある問い合わせ（LQ）

使い始めに来そうな問い合わせと回答。窓口回答標準化ツール（madoguchi-kaito）の台帳として書き出せます。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 大分類 | 必須 |  |
| 小分類 | 必須 |  |
| よくある問い合わせ | 必須 |  |
| 標準回答 | 必須 |  |
| 根拠（文書名・条など） |  |  |
| 担当の係 |  |  |

## 見本

画面の「見本案件（放課後児童クラブの利用申請）を読み込む」で、架空の市の案件を表示できます。前の工程の工程票も見本のものを読み込みます。

## AIアプリから使う

リポジトリの `mcp/` にあるMCPサーバーを Claude Desktop か LM Studio に登録すると、AIアプリがこの工程の工程票を読み書き・点検できます。手順はリポジトリ直下のREADMEにあります。
