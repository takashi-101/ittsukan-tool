# テスト（検収）（一気通貫ツールの工程5）

## 概要（30秒で読めます）

- **この工程で詰まっている会社向け**：できあがったものを、何をもって受け取ってよいか判断できない。
- この画面で、頼んだとおりにできているかを、要件ごとに確かめて受け取るかを決める。
- 結果は「工程票（こうていひょう）」というJSONにまとまり、次の工程で読み込めます。人が読む用のMarkdownでも書き出せます。
- AIを使わなくても、入力・点検・書き出しはすべて動きます。入力した内容はブラウザの中にだけ保存し、どこにも送信しません。
- このフォルダだけを取り出しても動きます（`index.html` をブラウザで開くだけ）。

## 入力と出力

| | 内容 |
|---|---|
| 前の工程の工程票（任意） | 要件定義、実装（試作とデバッグ） |
| この工程で書くもの | 要件ごとの確認項目（TC）、依頼と出力（TR）、依頼と出力の食い違い（TM）、検収の判断（TA） |
| 書き出すもの | `05-test.json`（工程票）、`05-test.md`（人が読む用） |

## この工程の道具

- 必要な機能から、確認項目の下書きを作る
- 依頼と出力の食い違いを、自分のAIアプリで判定する（判定の依頼文を作り、返答を貼り付けて読み込む）
- AIが決めたことチェック（ai-decision-audit）の記録と同じ形で書き出す

## 点検（AIは使わない）

入力のたびに、決まりで次を調べて「点検の結果」に出します。

- 必須の欄の空き
- 「もとになった項目」の番号が、前の工程の工程票につながるか
- 確認項目（テスト）の無い必須の機能（要対応）
- 結果が未実施の確認項目（参考）
- 不合格の確認項目（要対応）
- 採る・採らないが未選択の印（要対応）
- 「架空の基準」と書いた決まり（参考。本番の前に実在の基準へ置き換える）

## 欄の説明

### 要件ごとの確認項目（TC）

必要な機能（R）ごとに、何をしてどうなれば合格かを書きます。要件定義の工程票から下書きを作れます。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 確認すること | 必須 |  |
| 確かめ方（操作） | 必須 |  |
| 合格の条件 | 必須 |  |
| 結果 | 必須 | 未実施・合格・不合格 |
| メモ |  |  |

### 依頼と出力（TR）

AIに渡した依頼文と、AIが返した出力（試作のコードや文章）。食い違いの印の対象です。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 名前 | 必須 |  |
| 依頼文 | 必須 |  |
| AIの出力 | 必須 |  |

### 依頼と出力の食い違い（TM）

頼んでいないのにAIが決めたこと（落とした・足した・選んだ・寄せた）。AIが決めたことチェック（ai-decision-audit）と同じ印です。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 印の種類 | 必須 | 落とした・足した・選んだ・寄せた |
| 出力の該当箇所（無ければ「なし」） | 必須 |  |
| 依頼文の対応箇所（無ければ「なし」） | 必須 |  |
| 理由（一行） | 必須 |  |
| 採る・採らない | 必須 | 未選択・採る・採らない |
| メモ |  |  |

### 検収の判断（TA）

確認の結果をふまえて、受け取るかどうか。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 判断 | 必須 | 受け取る・直してから受け取る・受け取らない |

## 見本

画面の「見本案件（放課後児童クラブの利用申請）を読み込む」で、架空の市の案件を表示できます。前の工程の工程票も見本のものを読み込みます。

## AIアプリから使う

リポジトリの `mcp/` にあるMCPサーバーを Claude Desktop か LM Studio に登録すると、AIアプリがこの工程の工程票を読み書き・点検できます。手順はリポジトリ直下のREADMEにあります。
