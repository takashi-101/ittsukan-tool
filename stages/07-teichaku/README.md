# 定着（運用・引継ぎ）（一気通貫ツールの工程7）

## 概要（30秒で読めます）

- **この工程で詰まっている会社向け**：使い始めたが、担当が替わると回らなくなりそう。
- この画面で、担当が替わっても回るように、手順書と判断の分かれ目を残す。
- 結果は「工程票（こうていひょう）」というJSONにまとまり、次の工程で読み込めます。人が読む用のMarkdownでも書き出せます。
- AIを使わなくても、入力・点検・書き出しはすべて動きます。入力した内容はブラウザの中にだけ保存し、どこにも送信しません。
- このフォルダだけを取り出しても動きます（`index.html` をブラウザで開くだけ）。

## 入力と出力

| | 内容 |
|---|---|
| 前の工程の工程票（任意） | 導入（リリース） |
| この工程で書くもの | 手順書（MP）、判断の分かれ目と引継ぎ（MH）、見直しの時期（MR） |
| 書き出すもの | `07-teichaku.json`（工程票）、`07-teichaku.md`（人が読む用） |

## この工程の道具

- 導入の手順から、手順書の下書きを作る
- 手順書と判断の分かれ目を、業務棚卸し・事務引継ぎ記録（gyomu-tanaoroshi）のJSONとして書き出す

## 点検（AIは使わない）

入力のたびに、決まりで次を調べて「点検の結果」に出します。

- 必須の欄の空き
- 「もとになった項目」の番号が、前の工程の工程票につながるか
- 手順書の無い導入の手順（参考）
- 見直しの時期が決まっていない手順書（要対応）
- 「架空の基準」と書いた決まり（参考。本番の前に実在の基準へ置き換える）

## 欄の説明

### 手順書（MP）

毎日・毎年の作業の手順。業務棚卸し（gyomu-tanaoroshi）の業務として書き出せます。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 業務名 | 必須 |  |
| 課名 | 必須 |  |
| 係名 | 必須 |  |
| 役割（個人名は書かない） |  |  |
| 頻度 | 必須 | 日・週・月・年 |
| 手順（1行に1つ） | 必須 |  |

### 判断の分かれ目と引継ぎ（MH）

経験が要る判断を、次の人に渡すための記録。業務棚卸しの「事務引継ぎ記録」と同じ欄です。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 判断の分かれ目（どこで・何を見て・どう決めたか） | 必須 |  |
| そう判断した理由 | 必須 |  |
| 他のやり方を取らない理由 |  |  |
| 例外の扱い |  |  |
| 渡せない部分とその理由（空欄でもよい） |  |  |
| 次の人への手順（言葉にできた部分だけ） |  |  |

### 見直しの時期（MR）

手順書や決まりを見直す時期と、見る人（係・役割）。

| 欄 | 必須 | 選べる値 |
|---|---|---|
| 見直すこと | 必須 |  |
| 時期 | 必須 |  |
| 見る人（係・役割） | 必須 |  |

## 見本

画面の「見本案件（放課後児童クラブの利用申請）を読み込む」で、架空の市の案件を表示できます。前の工程の工程票も見本のものを読み込みます。

## AIアプリから使う

リポジトリの `mcp/` にあるMCPサーバーを Claude Desktop か LM Studio に登録すると、AIアプリがこの工程の工程票を読み書き・点検できます。手順はリポジトリ直下のREADMEにあります。
